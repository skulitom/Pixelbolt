Codixel run log, 15 November 2026 (UK time), Windows 11 Pro (build 26200), AMD Ryzen 9 7950X3D, Node.js 24.19.0,
Python 3.13.9 with Pillow 12.0.0.

What we ran: Codixel's core library, core/pixel.js, at commit 604a9dcbcc4e386bc48188b5f7f49099f5d04db7 (2 November
2026, the newest commit on 15 November; the repository has no tags or releases). Codixel ships no example scripts
and no command line: its SKILL.md tells Claude Code to `require("<skill folder>/core/pixel.js")` and call the
effect functions it documents. We did the same from our own script, codixel_effects.cjs, with no AI agent or
language model involved, using each effect's default settings. The canvas size, frame count and time step are
ours, because the core leaves them to the caller; they are printed in the result file.

Why it qualified to run (our rules for running another tool): open source (MIT) from its official repository; one JavaScript
file whose only requires are Node's zlib and fs (P.load reads a PNG, P.save writes one); no fetch, http,
child_process, Math.random, Date or GPU calls; no package.json, dependencies or install scripts.

Measure (from a folder holding the two scripts and the clone; the work folder must not exist yet):
  python -I codixel_measure.py src/core/pixel.js codixel_effects.cjs run codixel-effects-604a9dc.json
That runs, for each effect, twice, each in a new folder:
  node codixel_effects.cjs src/core/pixel.js <flame|smoke|hellfire|beams> <new folder>
and then, for the palette check, once each with
  --cols '<a PICO-8 subset>'      (the effect's own colour option)
  --quantize '<the 16 PICO-8 colours>'  (P.quantize(frame, 16, { palette }) on every frame)
Each run writes frames/fNN.png (P.save), sheet.png (P.pack, 8 columns, saved with P.save) and anim.gif (P.gif,
80 ms a frame). Where frames have see-through pixels (smoke), the GIF is made from frames drawn on a filled
background, as SKILL.md says ("A GIF cannot be see-through, so fill the background before making one"). Beams
mix into what is already drawn and flash the screen, so they are drawn on a filled background (24, 26, 38).

Effects and settings:
  flame    new P.Flame()  (defaults: height 48, width 14), 64x72 canvas, draw(buf, 32, 70, t), 24 frames, t = 0.08 s steps
  smoke    new P.Smoke()  (defaults: height 84, see-through alpha bands), 128x120 canvas, draw(buf, 64, 116, t), 24 frames
  hellfire new P.HellFire(64, 64), step(1, 2, 60) to warm up, then step(1, 2, 1) and draw per frame, 24 frames
  beams    P.volley(0, 3, { stagger: 0.15 }) on its default 240x135 screen, P.beams(buf, list, t) per frame, 20 frames

Reading the source (core/pixel.js at 604a9dc), for the table:
  - P.Flame, P.Smoke and their base P.Flow: one value per pixel from a shape plus moving fbm noise, cut at a
    threshold and turned into ramp colours with a 4x4 Bayer dither (P.ditherIndex). No simulation.
  - P.HellFire and P.Breath: an integer heat grid that each step copies upward (outward for Breath) with random
    sideways jitter and decay, the classic Doom fire; SKILL.md calls it "the way old Doom fire works".
  - P.novaSmoke: noise and shapes as functions of time. P.volley and P.beams: lines with a bloom and a screen flash.
  - Water: P.reflect (mirrored rows with ripples) and P.mist (see-through spray) for scenes; SKILL.md suggests
    extending P.Flow for a waterfall. No fluid solver, velocity field or pressure anywhere in the file.
  - Obstacles: Flow.draw(buf, x, ground, t) and HellFire.draw(buf, x, ground) take none; Breath.draw takes a
    `floor` y below which nothing is drawn.
  - Randomness: P.rng (seeded), xorshift seeds with fixed defaults, P.hash noise; no Math.random.
  - Output: P.png writes 8-bit RGBA PNG; P.gif writes GIF89a with up to 256 colours (more are reduced with
    P.quantize), on/off transparency; P.pack lays frames in a grid and returns its frame size, columns and count
    in code (no atlas file is written). No engine files.
